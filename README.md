# 顧家醫療｜月考核線上填寫

網頁放在 GitHub Pages，資料寫進 Google 試算表。

```
評核人（護理長／行政組長／藥師督導／督導）
   │ 用手機或電腦登入網頁填寫
   ▼
GitHub Pages 網頁 ──► Google Apps Script（API）──► Google 試算表「評核紀錄」
                                                  │
                         督導覆核 → 醫務營運經理核定 ┘
                                                  ▼
                              人資在試算表選單「月考核 › 產生獎金表」
```

## 資料夾內容

| 檔案 | 放哪裡 |
|---|---|
| `web/index.html`、`web/app.js`、`web/style.css`、`web/config.js` | GitHub 儲存庫（Pages 網站） |
| `apps-script/Code.gs` | Google 試算表 › 擴充功能 › Apps Script |
| `人員名單與帳號範本.xlsx` | 內容貼進 Google 試算表的「帳號」「人員名單」 |

---

## 一、建立 Google 試算表與 API（約 10 分鐘）

1. 在 Google 雲端硬碟新增一份試算表，命名為「月考核資料」。**只分享給人資**。
2. 選單「擴充功能 › Apps Script」，把預設的 `Code.gs` 內容全部刪掉，貼上 `apps-script/Code.gs`，按儲存。
3. 編輯器上方的函式選單選 `setup`，按「執行」。第一次會要求授權：選你的帳號 › 進階 › 前往（不安全）› 允許。
   - 完成後試算表會出現：設定、帳號、人員名單、評核紀錄、操作紀錄、題目對照。
4. 打開 `人員名單與帳號範本.xlsx`：
   - 「帳號」工作表第 2 列起整段複製，貼到 Google 試算表的「帳號」。
   - 「人員名單」同樣貼到「人員名單」。
   - 照範本「說明」頁修改：正式員工編號、主管姓名、主管所屬分院。
5. 在「設定」工作表的「開放月份」填 `2026-10`（多個月份用逗號：`2026-09,2026-10`）。
6. 部署 API：右上角「部署 › 新增部署作業」
   - 類型：網頁應用程式
   - 執行身分：**我**
   - 誰可以存取：**所有人**（網頁在 GitHub 上，必須選這個；資料仍由帳號＋PIN 保護）
   - 按「部署」，複製「網頁應用程式網址」（結尾是 `/exec`）。

> 之後若修改 `Code.gs`：部署 › 管理部署作業 › 鉛筆圖示 › 版本選「新版本」› 部署。網址不會變。

## 二、放上 GitHub Pages（約 5 分鐘）

1. GitHub 新增儲存庫，例如 `gu-review`（免費帳號的 Pages 需要 Public；程式裡沒有任何員工資料，資料都在試算表）。
2. 把 `web/` 資料夾裡的 4 個檔案上傳到儲存庫根目錄。
3. 編輯 `config.js`，把 `API_URL` 換成第一步複製的 `/exec` 網址，Commit。
4. 儲存庫 Settings › Pages › Source 選 `Deploy from a branch`，Branch 選 `main` / `/ (root)` › Save。
5. 約 1 分鐘後網址會出現：`https://你的帳號.github.io/gu-review/`。

## 三、每月操作（人資）

| 時間 | 動作 |
|---|---|
| 月初 | 「設定 › 開放月份」加上要評核的月份；確認人員名單（新進加一列、離職「在職」改 N） |
| 評核期間 | 試算表選單「月考核 › 檢查未完成名單」看誰還沒填、卡在哪一關 |
| 全部核定後 | 「月考核 › 產生獎金表」輸入月份，會產生 `獎金_YYYY-MM` 工作表 |
| 發放後 | 從「開放月份」移除該月份 → 該月資料鎖定，任何人都不能再修改或覆核 |

## 規則（與 GU-HR-F00 考核表相同）

- **同仁（護理 19 題、行政 20 題、藥師 20 題）**：1–5 分自動換點值；核算點值 = MAX(0, 1 + 浮動點值)。
- **主管（12 項，100 分制）**：≥90→3.0、85–89→2.0、80–84→1.5、70–79→1.3、<70→1.0。
- **主管紀實必填**：同仁有任何一題給 5 分或 1–2 分；主管有任何一項給滿分或一半以下。
- **點值不公開**：網頁只顯示題目與評分說明，不顯示點值、總分、級距或核算結果；換算規則只存在 Apps Script 與試算表。
- **獎金**：
  - 同仁獎金池 = 基本獎金 × 該分院該職類人數；主管獎金池 = 基本獎金 × 該職類人數。
  - 個人獎金 = 池 ÷ 點值合計 × 個人點值，只計算「已核定」的紀錄。
  - 基本獎金在「設定」工作表修改。
- **覆核流程**（依人員名單的覆核人欄位）：
  - 評核人送出後，狀態依序為「待覆核 → 待核定 → 已核定」。
  - 沒有覆核人的（藥師）送出即「已核定」。
  - 任一關可「退回」並寫原因；評核人修改後重新送出，從第一關重跑。
  - 還沒有人覆核前，評核人可自行修改。
  - **覆核人可調整分數**：覆核時按「調整分數」直接改選，必填調整說明，送出即同時通過。評核人原始分數保留在 Q1–Q20，調整後的分數與說明存在「覆核1／覆核2」欄位；核算點值以最後版本計算，「原始核算點值」保留評核人版本。評核人在網頁上看得到哪幾題被調整與說明。
- **網頁上看不到獎金金額**，只有人資在試算表看得到。

## 安全

- 每位評核人有自己的帳號＋PIN（6 碼）。PIN 輸錯 5 次鎖 15 分鐘；登入 6 小時後需重新登入。
- 每個人只看得到自己要評、要覆核的人；所有登入、送出、覆核、退回都記在「操作紀錄」。
- 有人離職或 PIN 外流：在「帳號」改 PIN 或「啟用」改 N，立即生效。
- 試算表本身只分享給人資。

## 從 v1 更新到 v2

1. Apps Script：全選刪除舊程式 → 貼上新的 `Code.gs` → 儲存 → 執行一次 `setup`（只會在「評核紀錄」最右邊補新欄位，不會刪資料）。
2. 部署 › 管理部署作業 › 鉛筆 › 版本選「新版本」› 部署（網址不變，config.js 不用改）。
3. GitHub：上傳新的 `index.html`、`app.js`、`style.css` 覆蓋舊檔（檔名要完全一樣）。
